# DevOps Git Project

## Overview

This project demonstrates Git and GitHub best practices for managing a DevOps project.

## Objectives

- Initialize and manage a Git repository
- Use feature, development, and main branches
- Create meaningful commits
- Use Pull Requests for merging
- Maintain project documentation
- Use `.gitignore`
- Create Git tags/releases

## Branching Strategy

- `main` - Production-ready code
- `dev` - Development integration branch
- `feature/*` - Individual features or tasks

## Project Structure
1. Create project directory
2. Create README.md .gitignore file
3. Create other two branches dev and feature
4. git init working directory
5. Add remote origin 
6. Makes changes in each branch and push the changes seperately to the remote repository
7. Pull the changes from remote to local
8. Merge the branches
9. Resolve the conflicts
10. Add the changes to the local and then push to remote repository
# Git Workflow
1. Create a feature branch from dev.
2. Implement the required changes.
3. Commit changes with meaningful commit messages.
4. Push the feature branch to GitHub.
5. Create a Pull Request to dev.
6. Review and merge the Pull Request.
7. Merge tested changes from dev into main.
8. Create a version tag for releases.
